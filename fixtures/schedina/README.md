# Schedina fixtures

- `payout_vectors.json`: frozen payout, settle and floor-check vectors in integer micro-units, generated by `scripts/gen_payout_vectors.py` (run with `python3 -I`). The `pricing` crate (plan 1.B) and the `schedina` program (plan 1.C) both reproduce every number, so the payout the desk quotes is the payout the program mints. The algorithm is in the file's `_doc` field.
- `quote_vector.json` (plan 1.C): the canonical borsh layout of the desk-signed quote and cash-out messages (field list with offsets), one worked quote and one worked cash-out (inputs, message hex, ed25519 seed and public key, signature hex, the `Ed25519Program` instruction data, and the `open_pending` / `cash_out` instruction data). Generated by `programs/schedina/tests/quote_vector.rs`, which fails if the file disagrees with the program; regenerate from `programs/` with `SCHEDINA_WRITE_FIXTURES=1 cargo test --test quote_vector`. The same test submits both vectors to the program in LiteSVM.

## Signed messages (L1 contract C3)

- Quote, `77 + 85 n` bytes: `"schedina/quote/v1"` (17) ‖ program id (32) ‖ `n` as u32 LE (borsh `Vec` length) ‖ `n` legs of 85 bytes (`symbol_hash` 32, `game_id_hash` 32, `start_ts` i64, `side` u8, `price_u` u64, `m1_ppm` u32) ‖ `stake_u` u64 ‖ `odds_offered_u` u64 ‖ `quote_expires_at` i64. Hashes are sha256 of the UTF-8 Pascal symbol and of `display_attributes.game_page.game_id`.
- Cash-out, 99 bytes: `"schedina/cashout/v1"` (19) ‖ program id (32) ‖ ticket PDA (32) ‖ `c_u` u64 ‖ `ts` i64.

## Transaction rule (app 2.E, crank 2.C, desk 2.A)

Build every `open_pending` and `cash_out` transaction as **`[..., Ed25519Program verify, schedina instruction]`**:

- The verify instruction must be **immediately before** the schedina instruction. Anything may come earlier (wallets such as Phantom prepend compute-budget or guard instructions while signing, which shifts absolute indices; the program locates the verify relative to its own index from the instructions sysvar, `current - 1`).
- It carries **exactly one signature**, and all three instruction-index fields are `0xFFFF` (public key, signature and message inside the verify instruction itself): exactly what `new_ed25519_instruction_with_signature(msg, sig, pubkey)` builds. Offsets that point into another instruction are refused, because absolute indices break when a wallet prepends instructions.
- The public key is `Config.quote_signer`; the message is the desk's signed bytes, copied untouched.
- `open_pending(nonce, min_payout_per_unit_u, expires_at, is_tip, copied_from)` has **no quote argument**: the program decodes the verified message as the quote. A 5-leg quote with `copied_from` set and two compute-budget instructions is 1,203 bytes, under the 1,232-byte limit.
- `cash_out(quote)` takes the `CashOutMsg` as its argument, and the verified message must equal its borsh encoding.
